## 1. Executive Summary & Constraints

Phase 23 delivers hospital data governance and LAN operational stability:
1. **Duplicate Patient Detection & Merge** (Alias-Pointer model).
2. **Filtered Bulk Archival** (Admin-guided soft archive with financial dues invariant).
3. **Extended Permission Boundaries** (Admin-only enforcement via RBAC).
4. **LAN Workstation Status Monitoring** (Periodic local heartbeats and workstation registry).

### Critical Canonical Invariants
- **Database Trigger Immutability (Non-Negotiable)**:
  - `payments` table has trigger `trg_prevent_payment_tampering` forbidding modification of `patient_id`.
  - `clinical_encounters` table has trigger `trg_prevent_finalised_encounter_tampering` forbidding modification of `patient_id`.
  - Therefore, patient merging **MUST NOT** rewrite foreign keys on historical records.
- **Model: Alias Pointer Architecture**:
  - The secondary patient record is marked `is_active = False`, `merged_into_id = master_patient.id`, with `merged_at`, `merged_by_user_id`, and `merge_reason`.
  - Aggregations (timeline, visits, billing summaries, encounter histories) dynamically query:
    `WHERE patient_id = master.id OR patient.merged_into_id = master.id`.
  - Safe Undo: Undoing a merge simply clears `merged_into_id = NULL` and restores `is_active = True`. Zero historical financial or clinical rows are touched.
- **Open Visit Safety Guard (Fail-Closed)**:
  - Merging is strictly refused with HTTP 400 (`open_visit_conflict`) if either the master or secondary patient has an active or open visit (e.g. `ARRIVED`, `WAITING`, `IN_CONSULTATION`, or unclosed visit).
- **Financial Invariant on Archival (Hard Guard)**:
  - Archival is strictly blocked with HTTP 400 (`patient_has_outstanding_dues`) if the patient has any unpaid balance or dues (`dues > 0`).
- **Offline LAN Operation**:
  - Zero cloud telemetry or external network calls. Heartbeats communicate exclusively between LAN workstations and the local server.

## 2. Database Schema & Migration 0030

The next migration is `0030_patient_merge_archive_and_workstations.py`.

### A. Additions to `patients` Table
```sql
ALTER TABLE patients
  ADD COLUMN merged_into_id BIGINT REFERENCES patients(id) ON DELETE RESTRICT,
  ADD COLUMN merged_at TIMESTAMP WITH TIME ZONE,
  ADD COLUMN merged_by_user_id BIGINT REFERENCES users(id),
  ADD COLUMN merge_reason TEXT,
  ADD COLUMN is_archived BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN archived_at TIMESTAMP WITH TIME ZONE,
  ADD COLUMN archived_by_user_id BIGINT REFERENCES users(id),
  ADD COLUMN archive_reason TEXT;

CREATE INDEX ix_patients_merged_into_id ON patients(merged_into_id);
CREATE INDEX ix_patients_is_archived ON patients(is_archived);
```

### B. New `workstations` Table
```sql
CREATE TABLE workstations (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    hostname VARCHAR(120) NOT NULL UNIQUE,
    ip_address VARCHAR(64) NOT NULL,
    terminal_name VARCHAR(120),
    app_version VARCHAR(32),
    last_seen_at TIMESTAMP WITH TIME ZONE NOT NULL,
    last_user_id BIGINT REFERENCES users(id) ON DELETE SET NULL,
    last_username VARCHAR(120),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX ix_workstations_hostname ON workstations(hostname);
CREATE INDEX ix_workstations_last_seen_at ON workstations(last_seen_at);
```

## 3. RBAC & Permission Boundaries

In `backend/src/kalyan_api/core/permissions.py`:
- `Permission.PATIENT_MERGE = "patient:merge"`
- `Permission.PATIENT_ARCHIVE = "patient:archive"`
- `Permission.WORKSTATION_READ = "workstation:read"`

### Role Matrix Allocation
- `Role.ADMIN`: holds `PATIENT_MERGE`, `PATIENT_ARCHIVE`, `WORKSTATION_READ`.
- `Role.RECEPTION`: zero merge, zero archive, zero workstation read permissions.
- `Role.DOCTOR`: zero merge, zero archive, zero workstation read permissions.
- Tests in `test_rbac_matrix.py` verify this complete role boundary.

## 4. Duplicate Detection & Matching Logic

### Detection Heuristics
- Exact mobile match (`mobile = candidate.mobile`) AND normalized full name match:
  - Names normalized: `regexp_replace(lower(trim(full_name)), '\s+', ' ', 'g')`.
- Secondary match: Exact mobile match with Levenshtein / token similarity >= 80%.
- Suspicious pairs review query returns:
  - Primary (older) and secondary (newer) patient summaries.
  - Registration dates, visit counts, last visit date.
  - Status indicator (whether either has an open visit).

## 5. Alias Pointer Aggregation Points

To provide a seamless, consolidated patient record without touching foreign keys:
1. **Patient Timeline (`/patients/{id}/timeline`)**:
   Query all records where `patient_id = id OR patient.merged_into_id = id`.
2. **Visits & Appointments**:
   Display consolidated visit history for the master patient.
3. **Pending Dues & Financials**:
   Compute overall dues by aggregating visits across both master and merged records.
4. **Deactivated Record Handling**:
   - `GET /patients/{id}` on a merged record returns metadata `{is_active: false, merged_into_id: master.id, merged_into_urn: master.urn}`.
   - Frontend redirects to `/patients/{master.urn}` and displays:
     *"Merged Record: This record was merged from URN {secondary.urn} on {date} by {admin}."*
   - Token Generation & Check-in Desk: Attempting check-in for a deactivated/merged record is refused with a clear error.

## 6. LAN Workstation Heartbeat Architecture

1. **Client ping**:
   - The React application (`AppShell.tsx` or a global hook `useWorkstationHeartbeat`) issues a background `POST /api/system/heartbeat` every 30s.
   - Payload: `{ hostname: string, terminal_name: string, app_version: string }`.
   - Server reads client IP from `request.client.host` and active user from `current_principal`.
   - Upserts into `workstations` table.
2. **Admin Monitor (`/admin/workstations`)**:
   - Queries `GET /api/admin/workstations`.
   - Computes live status:
     - **ONLINE** (green pulse): `last_seen_at < 60s ago`.
     - **IDLE** (amber): `60s <= last_seen_at < 300s ago`.
     - **OFFLINE** (slate): `last_seen_at >= 300s ago`.
