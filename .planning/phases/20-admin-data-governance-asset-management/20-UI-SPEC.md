### 2. Patient Demographic Correction Interface (D-20-02, D-20-03, D-20-04)
- **Route:** `/admin/patients/correct`
- **Patient Lookup Bar:**
  - Search input with debounced server-side query.
  - Matches on URN, Name, Mobile, and Legacy URN (`legacy_urn`).
  - Search results display URN, Name, Age/Gender, Mobile, and Village/Address.
- **Correction Workspace:**
  - Left Column: Form Fields
    - URN: Displayed in disabled badge (strictly immutable).
    - Full Name, Guardian Name: Text inputs (`14px`, 44px min-height).
    - Gender: Segmented toggle ('M', 'F', 'O').
    - Age / DOB: Number input (0–150) and optional Date picker.
    - Mobile: 10-digit number input.
    - Address, District, State: Textarea and inputs.
    - Emergency Contact: Optional text input.
    - Allergies & Notes: Explicitly read-only with explanation: *"Clinical allergies and consultation notes are managed by reception and doctors and cannot be modified via administrative correction."*
    - Mandatory Justification: Multi-line textarea (`min_length = 5`) with label: *"Reason for Demographic Correction (Audited)"*.
  - Right Column: Live Diff Comparison Card
    - Two-column table comparing "Current Stored Record" vs "Proposed Correction".
    - Changed fields highlighted with `#8E1C3D` border and "Modified" badge.
    - Unchanged fields displayed in muted slate.
- **Submission & Concurrency:**
  - Primary CTA: "Apply Demographic Correction".
  - Opens modal dialog with destructive confirmation copy.
  - On submit: `PATCH /api/admin/patients/{id}/demographics` with payload `{ version_id, reason, ...fields }`.
  - Stale concurrency (HTTP 409): Mounts `ConflictBanner` with "Reload Patient Record" button.

### 3. Patient Import Centre — 8-Stage Pipeline (D-20-08 to D-20-14)
- **Route:** `/admin/imports`
- **Top Stepper Bar:**
  - Horizontal track with 8 numbered stages:
    1. `Upload` &rarr; 2. `Inspect` &rarr; 3. `Map` &rarr; 4. `Validate` &rarr; 5. `Resolve` &rarr; 6. `Preview` &rarr; 7. `Commit` &rarr; 8. `Reconcile`
  - Completed stages: Emerald circle with checkmark (`#047857`).
  - Active stage: Crimson circle with bold number (`#8E1C3D`).
  - Future stages: Slate border circle with gray number.
- **Stage 1: Upload:**
  - Drag-and-drop dropzone supporting `.csv` and `.xlsx` (max 10 MB).
  - Clear guidance on accepted file formats and Excel UTF-8 export recommendations.
- **Stage 2: Inspect:**
  - Automatic detection of encoding (`UTF-8`, `UTF-8-SIG`, `Windows-1252`), delimiter (comma, semicolon, tab), and total row count.
  - Preview table of first 5 raw rows.
  - CTA: "Confirm File Inspection".
- **Stage 3: Map:**
  - Auto-mapping engine matches file header columns to canonical patient fields:
    `full_name`, `guardian_name`, `gender`, `age_years` / `dob`, `mobile`, `address`, `district`, `state`, `emergency_contact`, `legacy_urn`.
  - Manual dropdown overrides for unmapped columns.
  - Unmapped file columns marked as "Ignored".
  - CTA: "Confirm Column Mapping".
- **Stage 4: Validate:**
  - Row-by-row validation against hospital business rules:
    - Required: `full_name`, `guardian_name`, `gender` ('M'/'F'/'O'), `age_years` (0–150), `mobile` (10 digits), `address`.
  - Metric summary: X Valid rows (green), Y Invalid rows (red).
  - Invalid rows table with specific cell error tooltips (e.g., "Mobile must be exactly 10 digits", "Missing guardian name").
  - CTA: "Run Batch Validation".
- **Stage 5: Resolve (Duplicate Detection):**
  - Candidate duplicates matched by: (a) mobile + address, (b) legacy URN match, (c) name similarity with identical mobile.
  - Duplicate Resolution Table:
    - For each flagged row, displays side-by-side comparison with existing patient.
    - Explicit choice per row: `Skip Row` (default) vs `Import as New`.
    - Bulk action: `Skip All Flagged Duplicates`.
    - Explicit notice: *"Hospital records are never overwritten. Selecting 'Import as New' will create a separate patient with a new URN."*
  - CTA: "Resolve Duplicate Records".
- **Stage 6: Preview:**
  - Consolidated Batch Summary Card:
    - Total Rows in File
    - Valid Records to Commit
    - Duplicates Skipped
    - Invalid Rows Held Back
  - Safety Warning: *"Committing will trigger an automatic pre-import safety backup. URNs will be sequentially allocated only for committed records. Import batches cannot be bulk deleted."*
  - CTA: "Commit Import Batch".
- **Stage 7: Commit (Automatic Backup Gate):**
  - Live progress display:
    - Step 1: `Running pre-import safety backup...` (calls `backup_service.create_backup_bundle()`).
    - If backup fails: Aborts immediately, displays red alert: *"Commit aborted. Safety backup could not be completed. Check storage space and retry."*
    - Step 2: `Allocating gap-free URNs and inserting records...`
    - Step 3: `Writing batch audit log...`
- **Stage 8: Reconcile:**
  - Success summary card:
    - URN Range Allocated: e.g., `KH-2026-0150` to `KH-2026-0210`.
    - Total Committed: 61 patients.
    - Skipped / Unresolved: 4 rows.
  - Action button: "Download Error Records" (generates CSV containing the 4 invalid/skipped rows with error explanation column for offline correction).

### 4. Patient Export Centre (D-20-15 to D-20-20)
- **Route:** `/admin/exports`
- **Scope Configuration Card:**
  - Date Range: Native Start Date and End Date pickers.
  - Department Selector: Dropdown (`All Departments`, `Physiotherapy`, `Ophthalmology`).
    - Scope rule: Includes patients who had an appointment in the selected department during the date window.
  - Patient Search Query: Optional text filter.
- **Field Selection Accordion:**
  - Group 1: Core Demographics (Checked by default)
    - Full Name, URN, Guardian Name, Gender, Age, Mobile, Address, District, State.
  - Group 2: Administrative Identifiers (Checked by default)
    - Emergency Contact, Legacy Hospital Number, Registration Date.
  - Group 3: Patient Profile Notes (Unchecked by default per D-20-18)
    - Allergies, Reception Patient Notes.
  - Group 4: Complete Clinical Content (Unchecked by default per D-20-16)
    - Encounters & Finalised Clinical Notes, Encounter Addenda, Specialty Assessments (Physiotherapy VAS & ROM / Ophthalmology OD & OS), Vitals & Calculated BMI, Diagnoses, Prescriptions, Treatment Plans & Session Logs.
- **Clinical Export Security Banner (D-20-15):**
  - Prominent amber alert when any Clinical Content checkbox is selected:
    *"Access Notice: You are exporting sensitive medical records and consultation notes. This action is permitted for administrative governance and is recorded in the permanent audit trail with your documented justification."*
- **Export Settings & Formula Neutralization:**
  - Export Format: Radio toggle between `CSV (UTF-8)` and `Microsoft Excel (.xlsx)`.
  - Mandatory Export Justification: Multi-line textarea (`min_length = 5`) with label: *"Documented Purpose / Justification for Export"*.
  - Formula Injection Security Notice: *"Values beginning with '=', '+', '-', or '@' will be prepended with a single quote to prevent automated formula execution."*
- **Streaming Delivery:**
  - Primary CTA: "Export Patient Dataset".
  - Streamed directly to browser via `POST /api/admin/exports`. File is never persisted on server disk.
  - Audit event `PATIENT_EXPORTED` recorded in transaction.

    - English Footer Text: Multiline textarea (`14px`).

### 6. Hospital Asset & Logo Management
- **Route:** `/admin/assets`
- **Active Hospital Logo Hero Card:**
  - Large thumbnail preview of current active hospital logo/crest.
  - Metadata: Filename, Dimensions (e.g. `512x512`), MIME type (`image/png`), File Size, Uploaded Date, Active Status Pill (`ACTIVE`).
  - Action button: "Upload Hospital Asset".
- **Upload Dropzone Modal:**
  - Accepts PNG, JPEG, WebP, SVG, and PDF documents (max 10 MB).
  - Asset Type selector: `Hospital Logo & Crest`, `Registration / Trust Certificate`, `Clinic Facility Photograph`.
  - File validation checks magic bytes on server before saving outside web root.
- **Immutable Asset Version History Table:**
  - Columns: `Preview Thumbnail`, `Asset Type`, `Filename`, `File Size`, `Uploaded By`, `Date Uploaded`, `Status` (`ACTIVE` / `ARCHIVED`).
  - Historical assets are **never deleted** because past printed receipts and prescriptions reference historical asset versions.
  - Deactivate action opens confirmation modal: "Deactivate Hospital Asset".
