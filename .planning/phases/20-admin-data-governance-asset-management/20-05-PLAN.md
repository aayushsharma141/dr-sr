<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin Client -> Demographic Correction API | Administrator submits demographic changes; server must verify `patient:correct` permission independently of Reception's `patient:update` |
| Patient Entity -> Historical Printout Snapshots | Correcting a patient record must NOT alter previously issued financial or clinical printouts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-10 | Tampering / Concurrency | `backend/src/kalyan_api/routers/admin_patients.py` | high | mitigate | Enforce `require_version(patient, payload.version_id, "patient")` with row locking (`with_for_update()`). Stale updates return HTTP 409 `version_conflict`. |
| T-20-11 | Repudiation | `backend/src/kalyan_api/services/audit_service.py` | medium | mitigate | Enforce mandatory `reason` string (`min_length=5`) in `AdminPatientDemographicCorrection` schema; write `PATIENT_CORRECTED` in same transaction with full before/after diffs. |
| T-20-12 | Integrity / Tampering | PostgreSQL `trg_prevent_payment_tampering` | high | mitigate | Update trigger `fn_prevent_payment_tampering()` so that `patient_name`, `patient_urn`, `patient_mobile`, and `patient_address` are strictly immutable once posted, preventing any backdoor modification to financial receipts. |
| T-20-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package-legitimacy verification. |
</threat_model>
