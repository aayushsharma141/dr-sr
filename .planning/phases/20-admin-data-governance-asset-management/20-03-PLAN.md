<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| File Upload -> Server Disk | Untrusted client bytes cross boundary into server storage |
| Public Logo Route -> File Streaming | Unauthenticated users access active hospital logo for login screen |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-05 | Tampering / Elevation | `backend/src/kalyan_api/services/asset_service.py` | high | mitigate | Validate magic bytes (JPEG `\xff\xd8\xff`, PNG `\x89PNG\r\n\x1a\n`, WebP `RIFF...WEBP`, SVG `<svg`, PDF `%PDF-`), enforce 10 MB limit, strip user filename and generate random UUID filename, store outside web root in `KALYAN_ASSETS_DIR`. |
| T-20-06 | Denial of Service / Repudiation | `backend/src/kalyan_api/routers/assets.py` | medium | mitigate | Forbid physical file deletion of historical assets; deactivation merely sets `is_active = False` so issued historical documents referencing past logos retain integrity. |
| T-20-07 | Information Disclosure | `backend/src/kalyan_api/routers/assets.py` | low | mitigate | Only `LOGO` type assets are served publicly via `GET /api/assets/active-logo`. Registration certificates and clinic photos require authentication and admin rights. |
| T-20-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package-legitimacy verification for any image handling utilities. |
</threat_model>

    2. Create migration `0015_hospital_assets.py` (revises `0014`):
       - Create table `hospital_assets`:
         - `id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
         - `asset_type VARCHAR(32) NOT NULL` (`LOGO`, `PHOTO`, `REGISTRATION_DOC`)
         - `filename VARCHAR(255) NOT NULL UNIQUE`
         - `original_filename VARCHAR(255) NOT NULL`
         - `mime_type VARCHAR(64) NOT NULL`
         - `file_size_bytes BIGINT NOT NULL`
         - `is_active BOOLEAN NOT NULL DEFAULT true`
         - `version INTEGER NOT NULL DEFAULT 1`
         - `uploaded_by_user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`

       - Grant permissions: `GRANT SELECT, INSERT, UPDATE ON hospital_assets TO kalyan_app;`.
    3. In `backend/src/kalyan_api/models.py`:
       - Define ORM model `HospitalAsset(Base)`.
    4. Create `backend/src/kalyan_api/services/asset_service.py`:
       - Max size: `MAX_ASSET_BYTES = 10 * 1024 * 1024` (10 MB).
       - Magic byte validator for PNG, JPEG, WebP, SVG, PDF.
       - `save_asset(session, file_bytes, original_filename, asset_type, user_id) -> HospitalAsset`:
         - If `asset_type == "LOGO"`, set previous active logos to `is_active = False` (new logo increments version).
         - Write to `cfg.assets_dir / filename` using `uuid.uuid4().hex + ext`.
         - Insert `HospitalAsset` record.
       - `deactivate_asset(session, asset_id, user_id) -> HospitalAsset`: sets `is_active = False`. Physical file is preserved.
