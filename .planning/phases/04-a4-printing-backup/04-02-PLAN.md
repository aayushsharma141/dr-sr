<task type="auto">
  <name>Task 1: Hot SQLite Backup & Verified Restore Pipeline Service</name>
  <files>app/services/backup_service.py</files>
  <read_first>app/db/connection.py, app/config.py, ARCHITECTURE.md, DECISIONS.md</read_first>
  <action>
    1. Implement `BackupService` in `app/services/backup_service.py`:
       - `create_backup(target_dir: Optional[str] = None) -> Path`:
         - Uses SQLite's native `sqlite3.Connection.backup()` to create an atomic, non-blocking hot backup snapshot.
         - Filename format: `kalyan_backup_YYYYMMDD_HHMMSS.db`.
         - Ensures target directory exists (defaults to `BACKUP_DIR` = `data/backups/`).
         - Returns absolute `Path` of created backup.
       - `verify_backup_integrity(backup_path: str) -> dict`:
         - Connects to backup SQLite file in read-only mode (`file:{path}?mode=ro`).
         - Runs `PRAGMA integrity_check;`. If result != 'ok', returns `{"valid": False, "error": "Integrity check failed"}`.
         - Runs record counts: `patients`, `treatment_cases`, `treatment_sessions`, `payments`.
         - Returns summary dict: `valid`, `file_size_bytes`, `patients_count`, `cases_count`, `sessions_count`, `payments_count`, `created_at`.
       - `list_backups() -> list[dict]`:
         - Scans `BACKUP_DIR` for `*.db` files.
         - For each file, inspects timestamp, file size, and quick stats.
         - Returns list ordered by modification time descending (newest first).
       - `restore_from_backup(backup_path: str) -> dict`:
         - Step 1: Pre-restore verification. Calls `verify_backup_integrity(backup_path)`. If invalid, aborts immediately.
         - Step 2: Creates temporary safety snapshot of current active DB (`live_db_pre_restore_YYYYMMDD_HHMMSS.bak`).
         - Step 3: Copies backup file to active DB path using SQLite backup API or atomic file replacement.
         - Step 4: Verifies live database integrity post-restore. If verification fails, automatically rolls back from safety snapshot.
         - Returns success status dict with restored record counts.
  </action>
  <verify>Unit tests verifying hot backup creation, integrity checking, corrupt file rejection, and verified restoration.</verify>
  <acceptance_criteria>
    - `create_backup()` creates a valid SQLite database with identical tables and row counts.
    - Corrupt or invalid files are rejected by `verify_backup_integrity()` without touching the live database.
    - `restore_from_backup()` creates a safety snapshot before replacing live data.
  </acceptance_criteria>
  <done>Backup service provides fail-safe hot backups and verified restore pipeline.</done>
</task>
