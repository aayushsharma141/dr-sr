# Plan 13-04: Clinical Encounters & Addenda API with Doctor Silo & Immutability

## Purpose
Implement clinical encounter recording, immutable finalisation, dated addenda, and strict doctor silo access controls (`D-03`, `D-04`, `EG-16`).

## Requirements Covered
- `CLN-01`: Doctor records an encounter with clinical notes for a patient; reception cannot read clinical note content.
- `CLN-02`: Doctor finalises a note, after which it is locked; later changes are recorded as dated addenda.

## Proposed Changes

### 1. `backend/src/kalyan_api/routers/encounters.py`
- Endpoints:
  - `POST /api/encounters`:
    - Role gate: `ENCOUNTER_WRITE` permission (Doctor only). Reception returns 403 Forbidden.
    - Fields: `patient_id: int`, `appointment_id: int | None`, `symptoms: str`, `clinical_notes: str`, `diagnosis: str`.
    - Automatically links `doctor_id = principal.doctor_id`.
    - If `appointment_id` provided, validates appointment belongs to this doctor and updates appointment status to `IN_CONSULTATION`.
    - Audited: `action="encounter.created"`.
  - `GET /api/encounters/{id}`:
    - Role gate: `ENCOUNTER_READ` permission (Doctor only). Reception returns 403 Forbidden.
    - Scope gate: Scoped to `principal.doctor_id` via `get_scoped_or_404(..., ScopeFamily.CLINICAL)`. Unauthorized access returns 404 Not Found.
    - Includes list of all attached `clinical_addenda` ordered by `created_at ASC`.
  - `GET /api/patients/{patient_id}/encounters`:
    - Role gate: Doctor only. Scoped to doctor's clinical views.
    - Returns past encounters history for this patient.
  - `PATCH /api/encounters/{id}`:
    - Draft edit endpoint with optimistic concurrency control `version_id`.
    - Gate: If `encounter.is_finalised is True`, rejects immediately with HTTP 400 Bad Request (`encounter_finalised_immutable`).
    - Updates clinical fields, increments `version_id`, logs audit row.
  - `POST /api/encounters/{id}/finalise`:
    - Finalises draft encounter note: sets `is_finalised = True`, `finalised_at = now()`.
    - If linked to an appointment, updates appointment status to `DONE`.
    - Audited: `action="encounter.finalised"`.
  - `POST /api/encounters/{id}/addenda`:
    - Role gate: Doctor only.
    - Fields: `addendum_text: str`.
    - Validates encounter exists, is scoped to this doctor, and is finalised.
    - Appends row into `clinical_addenda` with timestamp and user ID.
    - Audited: `action="encounter.addendum_added"`.

### 2. Integration Tests
- `backend/tests/test_clinical_encounters.py`:
  - Doctor creates and edits draft encounter.
  - Reception user attempting `GET /api/encounters/{id}` receives 403 Forbidden.
  - Reception user attempting `POST /api/encounters` receives 403 Forbidden.
  - Doctor A attempting to access Doctor B's encounter receives 404 Not Found.
  - Doctor finalises note -> subsequent PATCH returns 400.
  - Doctor appends 2 addenda -> returned in order with timestamps.
