# Plan 13-03: Appointment Status State Machine & Doctor Queue API

## Purpose
Implement appointment status state transitions with optimistic locking (`PATCH /api/appointments/{id}/status`), audit tracking, and doctor-scoped daily queue endpoint (`GET /api/doctor/queue`).

## Requirements Covered
- `APT-02`: Appointment status (Booked, Arrived, In consultation, Done, Cancelled, No-show) is tracked, and the doctor sees their day's queue in order.

## Proposed Changes

### 1. State Machine Validator
- In `backend/src/kalyan_api/services/appointment_service.py`:
  - Validate allowed transitions according to the state matrix:
    - `BOOKED` -> `ARRIVED`, `CANCELLED`, `NO_SHOW`
    - `ARRIVED` -> `IN_CONSULTATION`, `CANCELLED`, `NO_SHOW`
    - `IN_CONSULTATION` -> `DONE`, `CANCELLED`
    - Terminal states (`DONE`, `CANCELLED`, `NO_SHOW`) cannot transition to any state.
  - Require `cancellation_reason` when moving to `CANCELLED`.
  - Validate role permissions (e.g. only doctor can move to `IN_CONSULTATION` or `DONE`).

### 2. `PATCH /api/appointments/{id}/status`
- Payload: `status: AppointmentStatus`, `version_id: int`, `cancellation_reason: str | None`.
- Verifies `version_id` matching to protect against stale concurrent updates (HTTP 409 Conflict).
- Updates `status`, `status_updated_at`, `version_id += 1`.
- Emits audit row: `action="appointment.status_updated"`, diffing old and new status.

### 3. `GET /api/doctor/queue`
- Requires `DASHBOARD_DOCTOR` or `APPOINTMENT_READ` with `Role.DOCTOR`.
- Filters appointments for `principal.doctor_id` where `appointment_date = CURRENT_DATE`.
- Returns ordered list:
  1. `IN_CONSULTATION` first.
  2. `ARRIVED` sorted by `token_number` ascending (waiting room queue).
  3. `BOOKED` sorted by `token_number` ascending (upcoming).
  4. `DONE`, `CANCELLED`, `NO_SHOW` (completed/archived).

### 4. Integration Tests
- `backend/tests/test_appointment_status.py`:
  - Valid transition sequence test.
  - Invalid transition rejected with 422.
  - Concurrent status patch rejected with 409 conflict.
  - Queue ordering verified for doctor.
