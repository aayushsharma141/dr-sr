# Plan 16-01: Permission Activation & Audit Log Viewer REST API

## Purpose
Activate `AUDIT_READ`, unreserve it from `RESERVED` permissions catalogue, and build `GET /api/audit-logs` endpoint with multi-parameter filtering, pagination, and redaction verification.

## Requirements Covered
- `AUD-02`: Filter audit log by user, action, entity, date range; view before/after diffs; Admin-only access.

## Proposed Changes

### 1. `backend/src/kalyan_api/core/permissions.py`
- Move `Permission.AUDIT_READ` out of `RESERVED` mapping.
- Grant `Permission.AUDIT_READ` exclusively to `Role.ADMIN`.
- Reception and Doctor roles remain default-deny (403 Forbidden).

### 2. `backend/src/kalyan_api/schemas/audit.py`
- Pydantic models:
  - `AuditLogOut`: `id`, `occurred_at`, `actor_user_id`, `actor_username`, `actor_role`, `action`, `outcome`, `entity_type`, `entity_id`, `before_data`, `after_data`, `reason`, `ip`.
  - `AuditLogListResponse`: `items: list[AuditLogOut]`, `total: int`, `page: int`, `page_size: int`.

### 3. `backend/src/kalyan_api/routers/audit.py`
- `GET /api/audit-logs`:
  - Query parameters: `actor_username`, `action`, `entity_type`, `entity_id`, `date_from`, `date_to`, `outcome`, `page` (default 1), `page_size` (default 50, max 200).
  - Enforce `require(Permission.AUDIT_READ)`.
  - Order descending by `occurred_at`.

### 4. Wire in `main.py`
- Include `audit_router` under `/api`.

### 5. Automated Tests in `backend/tests/test_audit_api.py`
- Verify Admin can list, filter by action, actor, entity, date.
- Verify Reception and Doctor receive HTTP 403 Forbidden.
- Verify anonymous caller receives HTTP 401 Unauthorized.
- Verify sensitive keys (passwords, tokens) are never present in output.
