# Plan 16-05: Backup & Operations CLI and REST Endpoints

## Purpose
Expose backup creation, archive listing, restoration, and integrity inspection through both Admin-only REST API endpoints and headless server CLI subcommands.

## Requirements Covered
- `BAK-01`, `BAK-02`, `BAK-03`: Web API triggers and command-line interfaces for backup, restore, and integrity checks.

## Proposed Changes

### 1. `backend/src/kalyan_api/schemas/operations.py`
- Pydantic models:
  - `BackupCreateRequest`, `BackupOut`, `BackupArchiveListResponse`.
  - `RestoreRequest`, `RestoreResultOut`.
  - `IntegrityReportOut`, `IntegrityCheckItemOut`.

### 2. `backend/src/kalyan_api/routers/operations.py`
- `POST /api/operations/backups`: Trigger backup (`Permission.BACKUP_RUN`).
- `GET /api/operations/backups`: List local backup archives (`Permission.BACKUP_RUN`).
- `POST /api/operations/restore`: Trigger safe restore with pre-snapshot (`Permission.BACKUP_RESTORE`).
- `GET /api/operations/integrity`: Run live integrity inspection (`Permission.INTEGRITY_RUN`).

### 3. Extend `backend/src/kalyan_api/cli.py`
- `kalyan backup create [--destination <path>] [--label <label>]`
- `kalyan backup restore <archive_path> [--force]`
- `kalyan backup verify <archive_path>`
- `kalyan integrity check`

### 4. Automated Tests in `backend/tests/test_operations_api.py` and `test_cli_operations.py`
- Verify endpoints with Admin credentials.
- Verify Reception and Doctor receive 403 Forbidden.
- Verify CLI subcommands return exit code 0 on success.
