# Plan 16-03: Verified Safe Restore Engine & Pre-Restore Snapshot

## Purpose
Build the restore engine that verifies backup bundle checksums before modification, captures an automatic pre-restore safety snapshot of the active database, restores the database schema & data, synchronizes photo files, and asserts system readiness.

## Requirements Covered
- `BAK-02`: Verified restore into clean or existing environment, automatic pre-restore safety snapshot, corruption detection aborts restoration before database mutation.

## Proposed Changes

### 1. `backend/src/kalyan_api/services/backup_service.py` (Restore Extension)
- `restore_backup(archive_path: Path, force: bool = False) -> RestoreResult`:
  - 1. Validate `archive_path` exists and compute all SHA-256 hashes against `manifest.json`. If corrupted, raise `BackupCorruptedError` and abort immediately (zero DB changes).
  - 2. Automatically generate a pre-restore backup snapshot (`kalyan-prerestore-YYYYMMDD-HHMMSS.tar.gz`) of the current system state.
  - 3. Execute database restore using owner connection.
  - 4. Restore photo files from archive into `photos_dir`.
  - 5. Verify restored database health and revision.
  - 6. Record audit event `BACKUP_RESTORED`.

### 2. Automated Tests in `backend/tests/test_restore_service.py`
- Verify restore into clean database succeeds and reproduces all patients, payments, photos, and users.
- Verify corrupted archive is rejected and active database remains untouched.
- Verify pre-restore snapshot is created automatically prior to restoration.
