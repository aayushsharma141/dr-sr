# Plan 16-02: Checksummed Backup Engine & Manifest Generator

## Purpose
Build the core backup engine capable of taking full PostgreSQL dumps, bundling patient photos, generating a SHA-256 cryptographically verified manifest, and writing archive bundles to local or secondary drives.

## Requirements Covered
- `BAK-01`: Manual and scheduled backups, database dump + photos + manifest with SHA-256 checksums, second drive support, corruption detection.

## Proposed Changes

### 1. `backend/src/kalyan_api/services/backup_service.py`
- `create_backup(destination_dir: Path | None = None, label: str | None = None) -> BackupResult`:
  - Determine destination (`destination_dir` or `settings.backup_dir` or `backend/var/backups`).
  - Run database dump using `pg_dump` CLI or streaming table SQL exporter fallback.
  - Collect patient photo files from `settings.photos_dir`.
  - Calculate SHA-256 hash for every bundled file.
  - Generate `manifest.json` with timestamp, file list, sizes, and hashes.
  - Create compressed `.tar.gz` archive bundle.
  - Record audit event `BACKUP_CREATED`.
- `verify_backup_bundle(archive_path: Path) -> tuple[bool, str, dict]`:
  - Inspect `.tar.gz` without full extraction.
  - Verify every file's computed SHA-256 matches manifest entry.
  - Return invalid/corrupted warning if any byte has drifted.

### 2. Automated Tests in `backend/tests/test_backup_service.py`
- Test backup creation produces valid archive with manifest.
- Test tamper detection: mutating one byte in the archive causes checksum verification failure.
- Test secondary destination directory support.
