# Plan 15-04: Unified Patient Timeline REST API

## Purpose
Build endpoint `GET /api/patients/{patient_id}/timeline` aggregating appointments, clinical encounters, prescriptions, treatment packages, sessions, and payments into a chronological ledger.

## Requirements Covered
- `CLN-03`: One chronological patient timeline of encounters, sessions, and payments.
- Cross-role visibility: Accessible to Doctor, Reception, and Admin (`Permission.TIMELINE_READ`).

## Proposed Changes

### 1. `backend/src/kalyan_api/schemas/timeline.py`
- `TimelineItemOut`:
  - `event_type`: `'APPOINTMENT'`, `'ENCOUNTER'`, `'PRESCRIPTION'`, `'TREATMENT_PLAN'`, `'TREATMENT_SESSION'`, `'PAYMENT'`
  - `event_id`: BigInteger
  - `event_date`: DateTime(timezone=True)
  - `title`: str (e.g. "Consultation Note", "Treatment Session #2", "Payment Received - ₹500")
  - `subtitle`: str | None (e.g. "Dr. Dwivedi", "Cash · Receipt #RCP-2026-0004")
  - `summary`: str | None (symptoms, diagnosis, modalities, amount)
  - `badge`: str | None (e.g. "DONE", "FINALIZED", "ACTIVE", "PAID", "REVERSED")
  - `details`: dict[str, Any]

### 2. `backend/src/kalyan_api/routers/timeline.py`
- `GET /api/patients/{patient_id}/timeline`:
  - Verify patient exists.
  - Query appointments, encounters (respecting doctor silo if Doctor role), prescriptions (respecting doctor silo), treatment plans, sessions, and payments.
  - Merge and sort descending by event timestamp.

### 3. Automated Tests in `backend/tests/test_timeline_api.py`
- Verify timeline returns all 6 event types in chronological order.
- Verify Doctor silo filters other doctors' clinical notes and prescriptions while retaining payments and appointments.
- Verify Reception reads timeline with clinical encounters hidden or masked per policy.
