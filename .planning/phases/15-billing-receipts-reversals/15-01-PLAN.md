# Plan 15-01: Schema Migration & Core Models (0005 Billing, Receipts & Reversals)

## Purpose
Define SQLAlchemy models for `ReceiptSequence` and `Payment`, write check constraints, and generate Alembic revision `0005_billing_receipts_and_reversals.py` with triggers for payment immutability and package payment limits.

## Requirements Covered
- `BIL-01`, `BIL-02`, `BIL-05`
- Database invariants: `amount_paise > 0`, `is_reversed` integrity, trigger-enforced tampering prevention, trigger-enforced overpayment rejection.

## Proposed Changes

### 1. `backend/src/kalyan_api/models.py`
Add models:
- `ReceiptSequence`: `id`, `cycle_key`, `last_number`, `updated_at`.
- `Payment`: `id`, `receipt_number`, `patient_id`, `treatment_plan_id`, `appointment_id`, `amount_paise`, `payment_method`, `notes`, `is_reversed`, `reversal_reason`, `reversed_by_user_id`, `reversed_at`, `created_by_user_id`, `created_at`.
- Add relationships on `Patient`, `TreatmentPlan`, `Appointment`, `User`.

### 2. Alembic Migration `0005_billing_receipts_and_reversals.py`
- Create `receipt_sequences` table with unique constraint on `cycle_key`.
- Create `payments` table with indexes on `receipt_number`, `patient_id`, `treatment_plan_id`, `appointment_id`.
- Add check constraints: `ck_payments_amount_positive`, `ck_payments_payment_method`, `ck_payments_reversal_integrity`.
- Add trigger `trg_prevent_payment_tampering` blocking DELETE and unauthorized UPDATE.
- Add trigger `trg_enforce_package_payment_limits` preventing overpayment on treatment packages.

### 3. Automated Tests in `backend/tests/test_billing_models.py`
- Verify check constraints: negative/zero amount rejected.
- Verify invalid payment method rejected.
- Verify reversal integrity check constraint.
- Verify immutability trigger blocks SQL DELETE.
- Verify immutability trigger blocks direct SQL tampering on payment amount/method.
- Verify package payment limit trigger blocks overpayment.
