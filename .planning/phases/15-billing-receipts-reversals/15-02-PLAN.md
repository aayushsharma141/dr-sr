# Plan 15-02: Atomic Receipt Sequence Service & Concurrency Stress Test

## Purpose
Build `kalyan_api.services.receipt_service` providing `allocate_next_receipt_number()` using row-level locking (`SELECT ... FOR UPDATE`) on `receipt_sequences` supporting calendar year and financial year cycles, validated with a 20-thread concurrency test.

## Requirements Covered
- `BIL-04`: Atomic gap-free sequential receipt numbering.
- Settings compliance: Format matches `receipt_sequence_cycle` (`CALENDAR_YEAR` -> `RCP-YYYY-XXXX`, `FINANCIAL_YEAR` -> `RCP-YY-YY-XXXX`).

## Proposed Changes

### 1. `backend/src/kalyan_api/services/receipt_service.py`
- `get_cycle_key(cycle: str, now: datetime) -> str`: Return cycle key string (`2026` or `2026-2027`).
- `allocate_next_receipt_number(session: Session, cycle: str = "FINANCIAL_YEAR") -> str`:
  - Determine cycle key and format.
  - Query `ReceiptSequence` with `.with_for_update()`.
  - Increment `last_number` atomically.
  - Format formatted receipt string: `RCP-{cycle_key}-{last_number:04d}`.

### 2. Automated Tests in `backend/tests/test_receipt_concurrency.py`
- 20 concurrent parallel threads requesting receipt numbers.
- Verify 20 unique receipt numbers returned, 0 duplicates, 0 gaps, strictly sequential.
- Verify both `CALENDAR_YEAR` and `FINANCIAL_YEAR` cycle formats.
