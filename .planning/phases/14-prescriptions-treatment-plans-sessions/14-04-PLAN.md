# Plan 14-04: Physiotherapy Sessions & Addenda REST API

## Purpose
Implement concurrency-safe session sequence allocation, VAS pain score validation, session logging endpoints, immutability protections, and retrospective addenda recording (`TRT-02`, `TRT-03`).

## Requirements Covered
- `TRT-02`: Chronological physiotherapy sessions with VAS score (0–10), clinician name, modalities, and observations.
- `TRT-03`: Finalized sessions immutable; corrections strictly by dated addenda.

## Proposed Changes

### 1. `backend/src/kalyan_api/services/session_service.py`
- `allocate_next_session_number(session, treatment_plan_id)`:
  - Uses `SELECT ... FOR UPDATE` row lock on `treatment_plans`.
  - Verifies plan is `ACTIVE`.
  - Verifies `completed_sessions < total_sessions`.
  - Returns `completed_sessions + 1`.

### 2. `backend/src/kalyan_api/schemas/treatment_sessions.py`
- `TreatmentSessionCreate`: `doctor_id`, `session_date`, `vas_score` (0..10), `modalities` (list of strings), `clinical_notes`.
- `TreatmentSessionOut`: full session attributes with allocated `session_number` and nested `addenda`.
- `TreatmentSessionAddendumCreate`: `note`.
- `TreatmentSessionAddendumOut`: addendum attributes with author user details.

### 3. `backend/src/kalyan_api/routers/treatment_sessions.py`
Endpoints:
- `POST /api/treatment-plans/{plan_id}/sessions`: Log new session (`TREATMENT_SESSION_WRITE`). Atomic numbering, automatic progress sync, audit event.
- `GET /api/treatment-plans/{plan_id}/sessions`: Retrieve sessions in chronological order (`TREATMENT_SESSION_READ`).
- `PATCH /api/treatment-sessions/{id}` & `DELETE /api/treatment-sessions/{id}`: Return `400 Bad Request` (immutable record).
- `POST /api/treatment-sessions/{id}/addenda`: Add dated amendment note (`TREATMENT_SESSION_ADDENDUM`).

## Verification
- Automated tests: `backend/tests/test_treatment_sessions_api.py` and `backend/tests/test_session_concurrency.py`
  - Validates 20 parallel threads logging sessions on same plan receive unique contiguous session numbers 1..20 with zero duplicates.
  - Validates VAS score boundary: rejects < 0 or > 10 with 422.
  - Verifies rejection of PATCH/DELETE on finalized sessions.
  - Verifies addendum chronological retrieval.
