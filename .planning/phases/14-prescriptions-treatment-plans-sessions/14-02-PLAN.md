# Plan 14-02: Prescriptions REST API

## Purpose
Implement Pydantic schemas, service layer, and FastAPI router for structured doctor prescriptions, itemized medication orders, and audit logging (`RX-01`).

## Requirements Covered
- `RX-01`: Doctor issues prescription with medicine name, dosage, frequency, duration, instructions, and advice; English content with static Hindi labels on print.

## Proposed Changes

### 1. `backend/src/kalyan_api/schemas/prescriptions.py`
- `PrescriptionItemCreate`: `item_order`, `medicine_name`, `dosage`, `frequency`, `duration_days`, `instructions`.
- `PrescriptionItemOut`: full item attributes with id.
- `PrescriptionCreate`: `patient_id`, `doctor_id`, `encounter_id`, `diagnosis`, `dietary_advice`, `general_advice`, `follow_up_date`, `items: list[PrescriptionItemCreate]`.
- `PrescriptionOut`: full prescription attributes with nested items list.

### 2. `backend/src/kalyan_api/routers/prescriptions.py`
Endpoints:
- `POST /api/prescriptions`: Doctor creates prescription (`PRESCRIPTION_WRITE` permission). In-transaction validation and audit event `prescription.created`.
- `GET /api/prescriptions/{id}`: View specific prescription (`PRESCRIPTION_READ`).
- `GET /api/patients/{id}/prescriptions`: List prescriptions for a patient (`PRESCRIPTION_READ`).

### 3. Permissions & Audit
- Permissions: `PRESCRIPTION_READ` (Admin, Reception, Doctor), `PRESCRIPTION_WRITE` (Doctor only).
- In-transaction audit trail for every prescription written.

## Verification
- Automated tests: `backend/tests/test_prescriptions_api.py`
  - Validates permission rules (reception/admin cannot create prescription; doctor can).
  - Validates duration_days >= 1, non-empty diagnosis and medicine items.
  - Verifies audit log entry created.
