    2. **Single Encounter per Appointment (DWS-01):** Doctor initiates encounter; subsequent creation request returns the active encounter instead of a duplicate.
    3. **Draft Auto-save & Versioning (DWS-02):** Partially populated draft saves with empty/partial text fields; verify `version_id` increments on update.
    4. **Vitals & Server BMI (DWS-06):** Doctor updates vitals with height (175 cm) and weight (70 kg); verify server returns calculated `bmi = 22.9` and enforces range constraints.
    5. **Specialty Templates (DWS-05):**
       - Test Physiotherapy encounter loads `PHYSIOTHERAPY_V1`, persists VAS pain score, ROM, and MMT responses.
       - Test Ophthalmology encounter loads `OPHTHALMOLOGY_V1`, persists side-by-side OD/OS visual acuity and IOP responses.
    6. **Prescription Lifecycle (DWS-07):**
       - Draft prescription with strength, form, and route.
       - Authorise prescription (`status = 'AUTHORISED'`).
       - Cancel prescription with valid reason (`status = 'CANCELLED'`).
       - Re-issue active prescription; verify encounter enforces at most one active prescription constraint.
    7. **Follow-Up Recommendation (DWS-08):**
       - Doctor records follow-up recommendation with date and clinical reason.
       - Query reception endpoint; verify recommendation appears with date and doctor but `clinical_reason` is strictly omitted.
       - Reception books recommendation into confirmed appointment.
    8. **Encounter Finalisation & Tamper Lock (DWS-02, D-19-09):**
       - Finalise encounter validating symptoms and diagnosis presence.
       - Attempt to modify symptoms, diagnosis, vitals, or template responses after finalisation; verify DB trigger blocks mutation.
    9. **Audited Cross-Doctor Read (DWS-04):**
       - Doctor B reads Doctor A's finalised encounter -> receives 200.
       - Verify `CROSS_DOCTOR_CLINICAL_READ` audit entry exists in `audit_logs`.
       - Doctor B attempts to edit Doctor A's encounter -> receives 404.
    10. **Single Session Concurrency & Takeover (DWS-10):**
       - Second login for user returns HTTP 409 `session_in_use`.
       - Second login with `takeover=True` succeeds, revokes prior session, and logs `SESSION_TAKEOVER`.
