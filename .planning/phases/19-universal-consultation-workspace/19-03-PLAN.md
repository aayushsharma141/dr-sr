<objective>
Execute Wave 3 of Phase 19: implement the prescription lifecycle (authorisation, print gating, cancellation with reason, re-issuance, and delivery metadata) and follow-up recommendations with clinical privacy isolation.

Deliverables:
1. Migrations 0013 and 0014 for prescription lifecycle, item fields (`strength`, `form`, `route`), and `follow_up_recommendations` table.
2. Prescription authoring and lifecycle router endpoints (`POST /prescriptions/{id}/authorise`, `POST /prescriptions/{id}/cancel`) enforcing single active prescription per encounter (D-19-14, D-19-15, D-19-16, DWS-07).
3. Follow-up recommendation engine supporting doctor creation, reception booking, overdue tracking, and strict omission of `clinical_reason` from reception endpoints (D-19-18, D-19-19, D-19-20, D-19-21, DWS-08).
</objective>

<execution_rules>
R-1 Target Test Database: All backend tests run against the configured test database via pytest.
R-2 Immutability of Authorised Records: An authorised prescription row cannot be updated; updates return 409 or 422.
R-3 Zero Clinical Leakage to Reception: Reception endpoints querying follow-ups must never select or return `clinical_reason`.
R-4 Synthetic Data Only: No real patient identifiers in tests or fixtures.
</execution_rules>

         - `updated_at TIMESTAMPTZ DEFAULT NOW() NOT NULL`
