# Plan 17-02: Power Cut Auto-Recovery & Startup Orchestration

## Purpose
Ensure the server PC automatically recovers after power cuts or hard restarts. When power is restored to the server machine, the database and API services must boot automatically without human operator intervention, verifying durability invariants.

## Requirements Covered
- `DEP-02`: Server auto-recovery after pull-the-plug power cuts, zero manual steps required to resume LAN operations.

## Proposed Changes
1. `deploy/register-autostart.ps1`:
   - Registers a Windows Scheduled Task (`KalyanHospitalServerAutoStart`) configured to run at system startup with `RunLevel Highest`.
   - Waits for PostgreSQL service (`postgresql-x64-18` or configured service) to be running before launching server.
2. `deploy/unregister-autostart.ps1`:
   - Cleanly unregisters the autostart scheduled task.
3. `deploy/health-check.ps1`:
   - Automated health verification script querying `http://localhost:8000/api/health`.
   - Asserts database readiness, schema revision, and durability settings (`synchronous_commit`, `fsync`).
4. Automated verification in `backend/tests/test_deploy_scripts.py`.
