# Plan 06-01: Baseline Audit & P0 Safety/Audit Core

## 1. Goal
Implement persistent audit logging, first-run administrator setup, and WAL-safe database restore snapshots.

## 2. Proposed Changes

### Task 1: Canonical `audit_logs` Schema & Migration
- File: `app/db/schema.sql`
  - Add `audit_logs` table:
    - `id INTEGER PRIMARY KEY AUTOINCREMENT`
    - `user_id INTEGER REFERENCES users(id)`
    - `actor_name TEXT NOT NULL`
    - `action TEXT NOT NULL`
    - `entity_type TEXT NOT NULL`
    - `entity_id TEXT`
    - `details TEXT`
    - `created_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))`
  - Add indexes: `idx_audit_logs_created_at`, `idx_audit_logs_action`, `idx_audit_logs_entity`.
- File: `app/db/connection.py`
  - In `_migrate(conn)`, ensure `audit_logs` table is created if it does not exist in legacy databases.

### Task 2: Implement `AuditService`
- File: `app/services/audit_service.py`
  - Methods:
    - `log_event(action, entity_type, entity_id=None, actor_name="System", details=None, user_id=None) -> int`
    - `get_recent_logs(limit=50, action=None, entity_type=None) -> list[dict]`
    - `get_entity_history(entity_type, entity_id) -> list[dict]`
- Wire `AuditService` into `AuthService`, `BackupService`, `PatientService`, and `TreatmentService`.

### Task 3: Secure First-Run Admin Setup in `AuthService`
- File: `app/services/auth_service.py`
  - Refactor `ensure_default_admin()`: do not seed a hardcoded production password by default. Provide `has_admin_user() -> bool` and `setup_initial_admin(username, password) -> dict`. For test/demo backward compatibility, provide explicit `seed_demo_admin()` only when requested by demo seeder or tests.
  - Update `tests/test_auth_service.py` and demo seeds.

### Task 4: WAL-Safe Pre-Restore & Rollback in `BackupService`
- File: `app/services/backup_service.py`
  - Replace `shutil.copy2` with `sqlite3.connect().backup()` for creating the safety rollback snapshot.
  - Run `PRAGMA wal_checkpoint(TRUNCATE);` before snapshotting and before database replacement.
  - In `verify_backup_integrity()`, verify that all canonical tables (`patients`, `treatment_cases`, `treatment_sessions`, `payments`, `users`, `audit_logs`) actually exist.

### Task 5: Verification & Regression Tests
- Create `tests/test_audit_service.py`.
- Run full pytest test suite to ensure all tests pass.

## 3. Verification Criteria
- `pytest tests/` passes with 100% green status.
- Audit logs capture actions accurately.
- Restore mechanism handles WAL databases without error.
