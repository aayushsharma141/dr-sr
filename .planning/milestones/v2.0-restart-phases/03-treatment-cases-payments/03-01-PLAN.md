  <name>Task 1: TreatmentRepository & TreatmentService (Cases & Chronological Sessions)</name>
  <files>app/repositories/treatment_repository.py, app/services/treatment_service.py</files>
  <read_first>app/db/schema.sql, app/db/connection.py, ARCHITECTURE.md</read_first>
  <action>
    1. Create `app/repositories/treatment_repository.py`:
       - `create_case(case_data: dict) -> int`:
         Inserts a record into `treatment_cases` (patient_id, title, no_of_sessions, total_amount_paise, start_date, notes) returning the new `case_id`.
       - `get_case(case_id: int) -> dict | None`:
         Fetches single case with patient details joined.
       - `get_cases_for_patient(patient_id: int) -> list[dict]`:
         Fetches all cases for a patient ordered by `created_at DESC`.
       - `update_case(case_id: int, update_data: dict) -> bool`:
         Updates case title, target sessions, total amount, status, notes.
       - `add_session(session_data: dict) -> int`:
         Inserts into `treatment_sessions` (case_id, session_timestamp, therapist_name, session_number, treatment_notes, modalities_used, pain_score) returning `session_id`.
       - `get_sessions_for_case(case_id: int) -> list[dict]`:
         Fetches all sessions ordered chronologically (`session_number ASC, session_timestamp ASC`).
       - `get_next_session_number(case_id: int) -> int`:
         Returns `COALESCE(MAX(session_number), 0) + 1` for the case.
       - `get_total_sessions_count(case_id: int) -> int`:
         Returns `COUNT(*)` of completed sessions for the case.
    2. Create `app/services/treatment_service.py`:
       - `open_treatment_case(patient_id: int, title: str, no_of_sessions: int, total_amount_rupees: float | int | str, notes: str = "") -> dict`:
         - Validates patient exists.
         - Validates `no_of_sessions >= 1`.
         - Converts rupees to integer paise (`round(float(amount) * 100)`).
         - Persists case and returns created case record.
       - `log_session(case_id: int, treatment_notes: str, therapist_name: str = "Dr. Chandan Kr. Dwivedi", modalities_used: str = "", pain_score: int | None = None, session_timestamp: str | None = None) -> dict`:
         - Validates case exists.
         - Validates `treatment_notes` is non-empty.
         - Validates `pain_score` is None or between 0 and 10.
         - Auto-computes next sequential session number.
         - Persists session and returns session record.
       - `get_case_with_history(case_id: int) -> dict`:
         - Returns case details along with chronological sessions list and completion progress (`completed_sessions / target_sessions`).
  </action>
  <verify>Unit tests verifying case creation, session numbering, and chronological retrieval.</verify>
  <acceptance_criteria>
    - Multiple treatment cases can be associated with a single patient.
    - Sessions are strictly returned in ascending chronological order with auto-incrementing session numbers.
    - Invalid pain scores (< 0 or > 10) or empty clinical notes raise descriptive `ValueError` or `ValidationError`.
  </acceptance_criteria>
  <done>Treatment repository and service manage cases and chronological clinical progress notes.</done>

<task type="auto">
  <name>Task 2: PaymentRepository & Currency-Safe BillingService (Integer Paise)</name>
  <files>app/repositories/payment_repository.py, app/services/billing_service.py</files>
  <read_first>app/db/schema.sql, DECISIONS.md, ARCHITECTURE.md</read_first>
  <action>
    1. Create `app/repositories/payment_repository.py`:
       - `record_payment(payment_data: dict) -> int`:
         Inserts into `payments` table (case_id, amount_paid_paise, payment_timestamp, payment_mode, reference_note, recorded_by). Returns payment `id`.
       - `get_payments_for_case(case_id: int) -> list[dict]`:
         Fetches all payments for a case ordered by `payment_timestamp ASC`.
       - `get_total_paid_paise(case_id: int) -> int`:
         Returns `COALESCE(SUM(amount_paid_paise), 0)` for the case.
       - `get_all_payments(limit: int = 100) -> list[dict]`:
         Fetches recent payment ledger records joined with patient and case details.
    2. Create `app/services/billing_service.py`:
       - Currency conversion helpers:
         - `rupees_to_paise(rupees: float | int | str) -> int`:
           Converts decimal or string rupees to exact integer paise without float inaccuracies (e.g., `Decimal(str(rupees)).quantize(Decimal('0.01')) * 100`).
         - `paise_to_rupees(paise: int) -> float`:
           Returns float rupees for display.
         - `format_inr(paise: int) -> str`:
           Formats as Indian Rupee string: e.g. `₹ 1,500.00`.
       - `record_installment(case_id: int, amount_rupees: float | int | str, payment_mode: str = "CASH", reference_note: str = "", recorded_by: str = "Staff") -> dict`:
         - Validates case exists.
         - Converts amount to `amount_paid_paise`.
         - Validates `amount_paid_paise > 0` (rejects 0 or negative amounts).
         - Queries current total paid and case total agreed fee.
         - Checks if `current_paid + new_payment > total_fee`: flags overpayment status (allowed with warning flag or recorded).
         - Persists payment in `PaymentRepository`.
         - Computes new `balance_paise = max(0, total_fee - (current_paid + new_payment))`.
         - Returns transaction receipt dictionary with prior paid, amount paid, remaining balance, and timestamp.
       - `get_financial_summary(case_id: int) -> dict`:
         - Returns: `total_fee_paise`, `total_paid_paise`, `balance_paise`, `is_cleared` (bool), `payment_count`, `payments_list`.
  </action>
  <verify>Unit tests verifying exact integer arithmetic, rejection of negative payments, and correct balance calculation.</verify>
  <acceptance_criteria>
    - All calculations use integer paise arithmetic (`total_fee_paise - sum(amount_paid_paise)`).
    - Payments <= 0 raise `ValueError("Payment amount must be greater than zero")`.
    - `format_inr` formats Indian Rupee amounts cleanly with `₹` symbol.
  </acceptance_criteria>
  <done>Payment repository and currency-safe billing service are operational.</done>
</task>
