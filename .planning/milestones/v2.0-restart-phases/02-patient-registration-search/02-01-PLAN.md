<task type="auto">
  <name>Task 1: Atomic ID Sequence Generator & PatientRepository</name>
  <files>app/repositories/__init__.py, app/repositories/patient_repository.py</files>
  <read_first>app/db/schema.sql, app/db/connection.py, ARCHITECTURE.md</read_first>
  <action>
    1. Create `app/repositories/__init__.py`.
    2. Implement `PatientRepository` in `app/repositories/patient_repository.py`:
       - `generate_next_urn(year: int | None = None) -> str`:
         Uses the `id_sequences` table in an immediate transaction (`BEGIN IMMEDIATE`) to increment `last_seq` atomically for the current year (e.g. `2026`). Returns formatted string `KH-YYYY-XXXX` (e.g., `KH-2026-0001`).
       - `create(patient_data: dict) -> int`:
         Inserts a record into `patients` using parameterized SQL (`?` placeholders). Returns the new record `id`.
       - `get_by_id(patient_id: int) -> dict | None`:
         Fetches single patient by primary key.
       - `get_by_urn(serial_urn_no: str) -> dict | None`:
         Fetches single patient by human-readable URN.
       - `update(patient_id: int, update_data: dict) -> bool`:
         Updates editable fields (name, age, sex, address, mobile, condition, referred_by, photo, patient_in, patient_out) and updates `updated_at` timestamp.
       - `soft_delete(patient_id: int) -> bool`:
         Sets `status = 'ARCHIVED'` (never physically drops rows).
       - `search(query: str, limit: int = 50) -> list[dict]`:
         Performs case-insensitive substring search matching against `serial_urn_no`, `patient_name`, or `mobile_no`.
  </action>
  <verify>Unit check verifying atomic URN generation increments sequentially without collision.</verify>
  <acceptance_criteria>
    - `generate_next_urn()` returns sequential IDs: `KH-2026-0001`, `KH-2026-0002`.
    - All SQL queries use parameterized queries (zero string formatting for SQL).
    - `search()` accurately matches by ID, name, or phone number.
  </acceptance_criteria>
  <done>Patient repository provides complete, parameterized data operations.</done>
</task>

<task type="auto">
  <name>Task 2: PatientService Validation & Photo Storage Manager</name>
  <files>app/services/patient_service.py</files>
  <read_first>app/repositories/patient_repository.py, app/config.py</read_first>
  <action>
    1. Implement `PatientService` in `app/services/patient_service.py` taking an optional `db_path`:
       - Uses `PatientRepository`.
       - `register_patient(data: dict, photo_source_path: str | None = None) -> dict`:
         - Validates required fields: `patient_name` (non-empty), `age` (0-125), `sex` in ('Male', 'Female', 'Other'), `mobile_no` (10 digits).
         - Auto-generates `serial_urn_no` if not provided.
         - If `photo_source_path` is provided, sanitizes extension (`.jpg`, `.jpeg`, `.png`), copies image to `PHOTOS_DIR / f"{serial_urn_no}{ext}"`, and records relative filename in database.
         - Calls `repository.create()`.
         - Returns full registered patient record.
       - `update_patient(patient_id: int, data: dict, new_photo_path: str | None = None) -> dict`:
         - Validates fields, updates photo if supplied, calls `repository.update()`.
       - `search_patients(query: str) -> list[dict]`:
         - Normalizes query string and calls `repository.search()`.
       - `get_patient(patient_id: int) -> dict | None`:
         - Fetches patient and attaches absolute photo path if file exists.
  </action>
  <verify>Verify `register_patient` rejects invalid mobile numbers and out-of-range ages with descriptive exceptions.</verify>
  <acceptance_criteria>
    - Validation error raised if name is empty, age < 0 or > 125, or mobile is not 10 digits.
    - Uploaded photo is copied to `PHOTOS_DIR` with sanitized filename.
  </acceptance_criteria>
  <done>Patient service enforces domain validation rules and safe file storage.</done>
</task>
